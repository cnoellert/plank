# Experimental macOS 15 Client fork

This fork adds an explicit Apple Silicon macOS 15 Client build target.
The initial goal is keyboard, mouse, video and audio from a Linux Host.
Mac Client tablet capture remains a separate implementation task. The Linux
tablet implementation is not part of the Mac binary.

## Build contract

Use the pinned dependencies and instructions in
[the Mac Client runbook](build/macos-client-build-runbook.md). Before dependency
bootstrap, application build and packaging, additionally set:

```bash
export PLANK_MAC_CLIENT_MIN_MACOS=15.0
```

Use a separate `PLANK_DEP_ROOT`, `PLANK_MAC_CLIENT_DEPS` and `PLANK_WORK_ROOT`
for each deployment target. Defaults remain 27.0. The Client target helper
requires Apple Silicon and an SDK at least as new as the selected target.
The Client builds its existing Rust transport with the same deployment target;
the macOS Host build policy is independent.

The source keeps the same pinned Qt 6.10.2, SDL 3.4.2, FFmpeg 9.0.1 (including
the identity-GBR patch), Opus, OpenSSL and Rust 1.89.0 inputs. The Client's
`Info.plist` minimum OS is generated by qmake from the selected deployment
target. Every dependency and the final application are checked for ARM64
Mach-O minimum-OS requirements. Package assembly repeats the check after
bundling Qt, plugins and private libraries.

```bash
python3 tests/packaging/test-macos-client-target.py -v
bash scripts/build/bootstrap-macos-client-deps.sh
bash scripts/build/build-macos-client.sh "$PLANK_SOURCE_ROOT" "$PLANK_WORK_ROOT/client-build"
```

Compilation produces a development application linked to the local dependency
tree. For a self-contained local development app:

```bash
bash scripts/package/stage-macos-client-dev.sh "$PLANK_SOURCE_ROOT" \
  "$PLANK_WORK_ROOT/client-build" "$PLANK_WORK_ROOT/client-dev-1"
```

The output directory must be new. The app is ad-hoc signed and marked as a
development build. It is not a notarized distributable. Public distribution
continues to use the existing signed DMG workflow and the fork owner's identity.

## Acceptance

Build and local tests establish only that the client runs on this OS. A Linux
Host session must separately establish exact-format decoding, Metal presentation,
frame pacing, audio, keyboard/mouse transforms, Retina/fullscreen behavior,
authentication and reconnect. Preserve profile negotiation and exact-format
software fallback; never make the port work by silently reducing chroma or
precision. A test fixture or loopback server does not qualify a live Host.

## Initial evidence — 2026-09-16

Tested on an M4 Max running macOS 15.7.4 with Command Line Tools/SDK 26.2:

- All pinned dependencies and the complete Client compiled. Full Xcode was
  not needed for this development app.
- 17 private dependency binaries and all 106 binaries in the self-contained
  app passed the ARM64 minimum-OS check. The app declares macOS 15.0.
- Client suites: output topology 18, toolbar 21, desktop/reconnect 7 passed.
- Transport unit tests: 21 passed, two ignored upstream tests. Five real QUIC
  loopback iterations passed both certificate modes (10 connection/close cases).
- The four target-selection/Mach-O regression tests passed, including rejecting
  dependencies built for macOS 26 and unresolved or mismatched plist metadata.
- All six portable root CTest suites passed. The bootstrap fixture supplies
  its own path and checksum helpers so GNU/BSD CLI differences do not determine
  whether its patch-provenance assertions execute.
- The self-contained app passed dependency closure, build-path and ad-hoc
  signature checks, launched offscreen with version `1.0.116-macos15-client`,
  and displayed its empty workstation list in the native desktop.
- Production 720p H.264 and HEVC 10-bit 4:4:4 identity fixtures both decoded
  through pinned FFmpeg software into full-range `gbrp10le`. A forced
  VideoToolbox HEVC fixture decode downloaded a `p410le` frame; the corresponding
  H.264 hardware probe did not succeed. These are FFmpeg fixture checks, not
  full Client Metal presentation or throughput tests.

No live Host session has been qualified. Audio, keyboard/mouse delivery,
streamed color/pixel equality, sustained frame pacing, Retina/fullscreen
mapping and reconnect remain live gates. The upstream Linux Host qualification
baseline remains Rocky 9.7; installation on older Rocky releases requires a
separate compatibility review. Mac Client tablet capture is not implemented.
