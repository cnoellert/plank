# PLANK 1.0.106 — macOS Host audio and display resilience

Host-only changes; existing Clients remain compatible. Linux Host, shared
Client, transport, authentication and codec/color behavior are unchanged.

- Streamed desktop audio follows the Mac's default output volume and mute.
  Physical-speaker suppression during capture remains enabled. Fixed-volume
  outputs use unity gain; failed control reads do not unexpectedly unmute.
- Audio-buffer overflow discards stale queued audio and resumes using actual
  source timestamps instead of permanently disabling capture.
- Other failures of an active desktop audio tap can restart audio independently
  of video/input, after complete teardown, with at most three retries per
  connection. Denied startup consent is not repeatedly requested.
- Audio failures now identify the failing stage; overrun and restart events
  are logged to the existing product log.
- Display recovery no longer reapplies settings to an existing offline virtual
  display, a path associated with a WindowServer abort. It requests wake and
  waits boundedly for the same output. A permanently unavailable display still
  fails clearly, without creating duplicate displays or rebooting the Host.

The operator validated volume/mute and reported good behavior on the candidate,
then approved merging. This is not exhaustive long-duration audio, output-device
switching or sleep/recovery qualification. The original audio interruption's
precise cause remains unproven; the new diagnostics distinguish failure paths.

The mainline installer is rebuilt from `main`, not a relabeled branch package.
See HANDOFF.md for exact source, hosted test/signing evidence and package hash.
Building/collecting this installer does not publish a GitHub Release or install
it on a workstation.
